==================================================
2. ภาพรวมระบบ
==================================================

ระบบนี้เป็น Single Page Application (SPA) สำหรับงานภายในบริษัท CSM SERVICE
สร้างด้วย Vanilla JavaScript แบบ ES Modules และใช้ Vite เป็น build tool

ระบบหลักแบ่งเป็น 6 กลุ่มงาน

1. Authentication / Account
2. Dashboard / Home
3. Engineering
4. HR Booking / Shuttle
5. HR Evaluation / Shift
6. Admin Tools

แหล่งข้อมูลหลักที่ระบบใช้งาน

- Firebase Realtime Database ฝั่ง Engineering
- Firebase Realtime Database ฝั่ง HR
- Firebase Storage สำหรับรูปแจ้งซ่อม
- Google Sheets สำหรับข้อมูลผู้ใช้, ประเมินผล, พนักงานกะ, รายงานเปลี่ยนเวร/กะ
- Gemini API สำหรับสรุปผลประเมินพนักงาน
- Open-Meteo API สำหรับ theme อากาศหน้า login

==================================================
4. Startup Flow ของระบบ
==================================================

ลำดับการเริ่มทำงานของระบบ

1. ผู้ใช้เปิด index.html
2. Browser โหลด CSS, CDN libraries, และ assets/js/main.js
3. main.js import
   - firebase.js
   - firebase-hr.js
   - router.js
   - auth.js
   - ui.js
4. main.js ตั้งค่า CSS variable --app-height ตาม viewport
5. auth.js ฟัง DOMContentLoaded
6. auth.js ทำงาน 3 ส่วนพร้อมกัน
   - ตั้ง auth mode เป็น login
   - โหลด weather theme หน้า login
   - โหลดรายชื่อแผนกสำหรับหน้า register จาก Google Sheets
7. auth.js ตรวจ localStorage
   - rememberedUser
   - autoLogin
8. ถ้าเปิด auto-login และ user active
   - อ่าน DHR/User/{empId} จาก Firebase EN
   - สร้าง sessionStorage
   - toggleView(true)
   - router แสดงหน้าตาม hash
9. ถ้าไม่มี auto-login
   - อยู่หน้า login จนผู้ใช้ submit form

Flow แบบย่อ

เปิดเว็บ
-> main.js
-> init Firebase + Router + Auth + UI
-> ตรวจ auto-login
-> ถ้าผ่าน: เปิด dashboard
-> router render page ตาม hash

==================================================
6. Authentication / Session / Permission Flow
==================================================

ไฟล์หลัก: assets/js/auth.js

6.1 Login Flow

1. ผู้ใช้กรอก username/password
2. auth.js อ่าน Firebase EN path DHR/User/{username}
3. ตรวจว่ามี user หรือไม่
4. ตรวจ password จากข้อมูลใน DB
5. ตรวจ active ว่าเป็น true หรือไม่
6. ถ้าผ่าน
   - เขียน sessionStorage
   - เขียน rememberedUser/autoLogin ลง localStorage ถ้าเลือก remember
   - toggleView(true)
   - เรียก showPage(getPageFromHash())

Session ที่ถูกเก็บ

- isLoggedIn
- empId
- empName
- empLastname
- empDepartment
- empActive
- empEmail
- empLevel_en
- empLevel_hr
- empLevel_it

6.2 Auto-login Flow

1. อ่าน localStorage
2. ถ้ามี rememberedUser + autoLogin=true
3. โหลด user จาก DHR/User/{empId}
4. ถ้า active
   - set session
   - เปิด dashboard

6.3 Register Flow

1. หน้า register โหลดรายชื่อแผนกจาก Google Sheets
2. ผู้ใช้กรอก employeeId, password, name, department, email
3. validate input
4. เรียก service registerUserAccount()
5. service จะสร้าง user พร้อมกัน 3 จุด
   - Firebase EN: DHR/User/{employeeId}
   - Firebase HR: DHR/User/{employeeId}
   - Google Sheet User Directory
6. ถ้าบางจุด fail มี rollback
7. ถ้าสำเร็จ redirect กลับหน้า login

6.4 Logout Flow

1. ผู้ใช้กด logout
2. showConfirmModal
3. ลบ localStorage rememberedUser/autoLogin
4. ล้าง sessionStorage
5. reload หน้าเว็บ

6.5 Permission Flow

Permission helper อยู่ใน utils.js

โปรไฟล์สิทธิ์หลัก

- isEngineeringAdmin
- isEngineeringDocAdmin
- isHrDocAdmin
- isHrDispatchAdmin
- isItAdmin
- isSystemAdmin

Page guard สำคัญ

- eng-auto-close -> admin system
- eng-doc -> engineering doc admin
- hr-doc -> hr doc admin
- hr-shuttle-group -> hr dispatch admin
- admin-access -> system admin
- admin-backup -> system admin

10.2 Engineering List / Approval / Work Tracking
------------------------------------------

ไฟล์หลัก: assets/js/pages/eng-list.js

หน้าที่

- แสดงรายการแจ้งซ่อม
- ตารางคิวอนุมัติ
- ตารางค้นหาย้อนหลัง
- modal รายละเอียด
- approve / edit / cancel / open work report

ข้อมูลถูกโหลดจาก

- DEN/FIX ทั้งหมด
- DHR/User สำหรับรายชื่อหัวหน้าช่าง/ช่าง

สถานะงานซ่อม

- 1 = รอหัวหน้าอนุมัติ
- 2 = รอช่างอนุมัติ
- 3 = กำลังซ่อม
- 4 = ซ่อมเสร็จแล้ว
- 5 = รอการประเมินความเรียบร้อย
- 6 = ยกเลิก

Flow โหลดข้อมูล

1. โหลด DEN/FIX ทั้งหมด
2. flatten จาก object -> array
3. split machine code / machine name
4. split reporter / approver name
5. เก็บ masterRecords
6. สร้างตาราง queue และตารางค้นหา
7. filter ตามสิทธิ์
   - admin เห็นทั้งหมด
   - approver เห็นงานที่ตนเกี่ยวข้อง

Flow approve หลัก

Step 1:
หัวหน้าอนุมัติ -> set step 2
บันทึก den_start, den_end, leaderApprove

Step 2:
admin_en/admin -> set step 3
กำหนดหัวหน้าช่าง/ช่าง
บันทึก adminApprove, den_start_real
สามารถเปิด report ใบงานได้

Step 3:
admin_en/admin -> set step 5
บันทึกวิธีซ่อม, อะไหล่, หมายเหตุ, den_end_real, closeApprove

Step 5:
หัวหน้าเดิมหรือ admin ยืนยันผล
- ถ้ารับงาน -> step 4
- ถ้าไม่รับงาน -> กลับ step 2 พร้อม remark

Flow edit

admin_en/admin แก้
- den_name
- den_fix
- den_parts
- den_remack
- den_start
- den_end

Flow cancel

approver/admin ยกเลิก -> step 6

Flow report

- ปุ่ม work เปิด reports/eng/reporteng01.html?id={recordId}

     -> set den_end_real/dateUpdate ใหม่
4. เก็บประวัติรอบล่าสุดไว้ใน memory/session state
5. มีปุ่ม Run now และ toggle เปิด/หยุด scheduler

20. สรุปภาพรวมสุดท้าย
==================================================

โปรเจคนี้เป็นศูนย์รวม workflow ภายในองค์กรหลายชุดในหน้าเดียว
โดยมีแกนกลางคือ

- SPA Router
- Session-based UI access
- Firebase EN/HR
- Google Sheets services
- รายงาน print แยกแท็บ

ภาพรวมการไหลของข้อมูลหลักคือ

UI Form / UI Action
-> Page Module
-> Service หรือ Firebase/Sheet API
-> บันทึกข้อมูล
-> กลับมา render ตาราง/รายงาน/สถานะใหม่

ถ้าจะต่อยอดโปรเจคนี้ในรอบถัดไป
จุดที่ควรมองเป็นลำดับแรกคือ

1. auth และ permission model
2. data contract ของ EN/HR/Firebase/Sheets ให้ชัดขึ้น
3. ลด logic ซ้ำระหว่าง hr-car / hr-shuttle / booking-list
4. แยก report/data transform utilities ออกจาก page file ขนาดใหญ่
